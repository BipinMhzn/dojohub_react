# Deployment — Wiki

---

## Overview

DojoHub is a full-stack Laravel 12 + React 19 + Inertia.js 2 application. Deployment requires both a PHP backend and compiled frontend assets. SSR (Server-Side Rendering) is enabled — a Node.js process runs alongside PHP to pre-render pages.

---

## Local Development

### Prerequisites

| Tool | Version | Notes |
|------|---------|-------|
| PHP | ^8.4 | Must be ≥8.4 (strict types, new array functions) |
| Composer | 2.x | Dependency manager |
| Node.js | 18+ | For Vite and SSR server |
| npm | 9+ | Package manager |
| MySQL | 8.0+ | Local DB (`dojohub_react` database) |
| Laravel Herd | latest | Recommended local environment (macOS) |

### Herd Setup (macOS)

```bash
# 1. Clone repo to ~/Herd/dojohub_react
# 2. Herd auto-detects the directory and creates dojohub_react.test

# 3. Install PHP dependencies
composer install

# 4. Install JS dependencies
npm install

# 5. Create environment file
cp .env.example .env
php artisan key:generate

# 6. Configure .env for local MySQL
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=dojohub_react
DB_USERNAME=root
DB_PASSWORD=

# 7. Run migrations + seed
php artisan migrate --seed

# 8. Create storage symlink
php artisan storage:link

# 9. Start Vite dev server
npm run dev
```

App is available at `http://dojohub_react.test` (Herd handles the PHP server).

### Running the Dev Server

Two processes must run simultaneously in local development:

| Process | Command | Purpose |
|---------|---------|---------|
| PHP | Managed by Herd | Serves Laravel |
| Vite HMR | `npm run dev` | Hot module replacement for React |

Vite's dev server runs on `http://localhost:5173` and injects assets via Laravel's `@vite` directive. Herd handles `dojohub_react.test`.

**SSR is not active in development** — `inertia.php` has `ssr.enabled = true` but the SSR Node server (`npm run build:ssr`) only needs to run in production.

## Building for Production

### 1. Frontend Build

```bash
# CSR build only (no SSR)
npm run build

# CSR + SSR build (required for production)
npm run build:ssr
```

`npm run build:ssr` runs two Vite passes:
1. `vite build` — outputs to `public/build/` (CSR assets)
2. `vite build --ssr` — outputs to `bootstrap/ssr/ssr.js` (Node SSR server)

The `public/build/manifest.json` is generated by the first pass and consumed by Laravel's `Vite::asset()` helper.

### 2. PHP/Composer

```bash
# Install production dependencies only
composer install --no-dev --optimize-autoloader

# Cache configuration for performance
php artisan config:cache
php artisan route:cache
php artisan view:cache
php artisan event:cache
```

### 3. Database

```bash
php artisan migrate --force
```

`--force` is required in production (`APP_ENV=production`) to bypass the safety prompt.

### 4. SSR Server

The SSR server is a Node.js HTTP server that Inertia's PHP package calls internally:

```bash
# Start SSR server (production)
node bootstrap/ssr/ssr.js
```

The SSR server listens on `http://127.0.0.1:13714` (configured in `config/inertia.php` as `ssr.url`). It must be running for server-side rendering to work. If it's down, Inertia falls back to client-side rendering.

To run as a background service:

```bash
# Using pm2 (recommended)
pm2 start bootstrap/ssr/ssr.js --name "dojohub-ssr"
pm2 save
pm2 startup
```

## Environment Variables

### Required for Production

```env
APP_NAME=DojoHub
APP_ENV=production
APP_KEY=base64:...         # php artisan key:generate
APP_DEBUG=false
APP_URL=https://yourdomain.com

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=dojohub_react
DB_USERNAME=dojohub
DB_PASSWORD=strong_password

SESSION_DRIVER=database
CACHE_STORE=database
QUEUE_CONNECTION=database

FILESYSTEM_DISK=public    # or 's3' if using AWS

VITE_APP_NAME="DojoHub"
```

### Optional

```env
# Auditing (disable in staging for performance)
AUDITING_ENABLED=true

# Mail
MAIL_MAILER=smtp
MAIL_HOST=smtp.example.com
MAIL_PORT=587
MAIL_USERNAME=...
MAIL_PASSWORD=...
MAIL_FROM_ADDRESS=noreply@yourdomain.com

# AWS S3 (for file storage)
AWS_ACCESS_KEY_ID=...
AWS_SECRET_ACCESS_KEY=...
AWS_DEFAULT_REGION=us-east-1
AWS_BUCKET=dojohub-uploads
```

## File Storage

Player profile photos and club logos are stored on the `public` disk by default:

```bash
php artisan storage:link   # creates public/storage → storage/app/public symlink
```

Files are accessible at `{APP_URL}/storage/{path}`.

For production S3 storage:
1. Set `FILESYSTEM_DISK=s3`
2. Configure `AWS_*` env vars
3. No symlink needed — S3 URLs are used directly

## Queue Worker

Jobs use the `database` driver in production (configured in `.env`). Run a worker:

```bash
php artisan queue:work --sleep=3 --tries=3
```

Or with Supervisor:

```ini
[program:dojohub-worker]
command=php /var/www/dojohub_react/artisan queue:work --sleep=3 --tries=3
user=www-data
autostart=true
autorestart=true
redirect_stderr=true
```

## Post-Deployment Checklist

```bash
composer install --no-dev --optimize-autoloader
npm ci
npm run build:ssr
php artisan migrate --force
php artisan config:cache
php artisan route:cache
php artisan view:cache
php artisan storage:link
# restart SSR server and queue worker
```

## Key File Locations

| Path | Purpose |
|------|---------|
| `public/build/` | Compiled frontend assets |
| `bootstrap/ssr/ssr.js` | Node SSR server bundle |
| `storage/app/public/` | User-uploaded files |
| `public/storage` | Symlink → `storage/app/public` |
| `bootstrap/cache/` | Config/route/view caches |
